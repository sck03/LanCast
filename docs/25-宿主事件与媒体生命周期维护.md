# 25 宿主事件与媒体生命周期维护（D21）

日期：2026-10-25；开发版本0.6.6 / 14。当前源码、构建运行和验证边界统一见[08](08-实施进度与审阅入口.md)。本次维护沿用现有四层Rust工作区和独立AirPlay模块，没有新增应用运行依赖。

## 修复依据与完成行为

- 宿主事件队列原先忽略非阻塞投递失败。C ABI回环已复现队列满后接收端停止、发送端收不到停止事件。现在积压过限会撤销核心并保留明确的终止错误，避免宿主继续使用不完整的信令历史。
- Android收到远端停止或会话错误时，原来只清空媒体状态，旧文件URL仍返回200，再分享报STOP_CURRENT_FILE_FIRST。现在所有结束路径经过完整停止或关闭，撤销原生文件/直播授权；旧文件失效后可创建新分享。
- 接收端最小feature测试原先因两个发送示例未声明required-features而编译失败，现已补齐声明并加入CI的两种最小feature测试。
- Windows/Apple产物校验原先依赖assert，Python -O下检查失效。现统一使用明确异常检查，保留原CLI入口，并增加普通/优化模式下拒绝无效产物的回归。

## 模块职责与扩展边界

| 模块 | 持有职责 | 扩展约束 |
|---|---|---|
| cast-adapters/events | 有界FIFO、统计合并、溢出终止、通知等待 | 不依赖Runtime、协议控制器或平台媒体；控制事件不得按统计策略丢弃 |
| core/ffi与JNI | 整数句柄、可中断等待、缓冲归还 | 等待不持有句柄注册表锁；原ABI 2入口保留，新增wait_poll不改变远端协议 |
| Android ControlSession / Apple CoreSession | 原生等待与至多一个待处理UI批次 | 每批最多32事件，关闭唤醒等待并拒绝旧回调；不能把积压转移到无限UI任务队列 |
| windows/media/video_pool | Media Foundation NV12样本租约和输出视图缓存 | 最大4样本；编码器持有时禁止复用，支持纹理数组的子资源索引 |
| receiver-contracts/WorkerCompletion | 媒体所有者实际退出的通知 | 纯Kotlin/JDK；每个参与者只完成一次，不引用MediaCodec或Service |
| scripts/windows_artifacts / artifact_checks | 可导入的产物验证与强制检查 | CLI只处理参数和报告写入；不得用assert执行发行校验 |

清理了没有生产调用的Coordinator、Grant/MediaSessionPort、QualityController，以及旧WSS断线续接和RetryBudget。实际路由规则、WSS会话所有权和cast-core/recovery保留。后续用例应接入已有真实状态所有者，避免再维护只在测试中运行的平行状态机。

## 宿主邮箱合同

邮箱最多256条、序列化数据总计2MiB、单事件128KiB；统计按会话合并，live.stats只保留最近一项。正常控制事件按FIFO交付。统计无法入队时可以省略，不能挤掉控制事件。

控制事件超过数量、字节或单条上限时，邮箱清除不完整的旧信令，保留一个error事件，body包含code=HOST_EVENT_QUEUE_OVERFLOW、terminal=true及requiresNewConsent=true，同时取消核心运行时。此后不接收普通事件。宿主必须释放媒体和旧控制句柄，再显式建立新连接；用户界面展示重新连接说明，机器错误码留在事件中。

lancast_wait_poll在宿主工作线程等待，最长1000ms，事件到达立即唤醒；shutdown打断等待。poll/free/destroy的所有权不变，所有返回缓冲仍由lancast_free_buffer归还。Android和Apple分别取消30ms/20ms空轮询；Windows保留原生消息循环，活动时50ms、空闲时500ms轮询。

原生核心取消会撤销其网络与文件资源；平台采集器由宿主在消费终止事件时关闭。不能把此合同描述为界面线程失去调度时仍可同步执行平台UI清理。

## 媒体资源与性能维护

Windows转换使用Media Foundation样本分配器，预建2个、最多4个NV12样本。编码器直接提交池样本，归还由Media Foundation跟踪样本引用；池满只跳过本次视频输入，音频和停止继续执行。输出视图最多4项、输入视图最多3项；视频处理器变化清除关联视图。编码器先销毁，再释放样本池。

Apple首帧探针在回调线程只允许一次通知，RTC队列随后撤销探针。Android AirPlay首帧回调解除MediaCodec监听，格式重建后不重复注册已经完成的探测。Android TS JNI使用非critical、只读且限于同步调用的数组借用，移除额外C++ vector复制；允许封装器调用Java输出，禁止把指针存入异步任务。

AirPlay关闭先清空队列并中断调度，各媒体线程在finally中独占回收解码器/声音输出，全部实际退出后才释放接收租约。生命周期执行器不再无限join媒体线程，原生引擎和发现撤销可以继续进行；两秒未完成时显示等待驱动释放，新来源仍不能占用旧租约。网络切换或重新启用须等待媒体、原生和发现三方退出。驱动永久卡死时不会强杀线程或错误宣称资源已释放。

## 验证与维护

本地Rust回环覆盖邮箱溢出后的终止错误与远端会话撤销、文件停止/重分享、统计合并、事件大小限制及等待唤醒。Python回归覆盖PE/hash/符号/架构和-O负向用例；JVM回归覆盖并发退出、重复完成及旧租约保持；Apple集成测试新增首帧探针并发通知检查。

video_pool_contract验证持有全部4个样本时不会复用，释放后能重新取得槽位；无硬件D3D11的CI宿主明确输出SKIP。本机硬件池验证通过不等于完整Windows录屏/硬编性能验收。五个平台继续通过现有产品构建脚本验证，具体提交和运行记录见08。

CPU/RSS、端到端延迟、音画同步、真实驱动故障和两小时长稳仍按[06](06-开发计划与验收.md)执行，不从减少分配或测试通过推导性能提升百分比。构建缓存按[24](24-发现任务与工作区维护.md)预览、验证后清理，第三方源码、许可证和原始媒体样本不作为无效文件删除。

# 16 Windows 易用性与桌面模块

决策 D13；日期：2026-10-08；应用版本：0.4.1 / 5，开发版。

## 用户操作与兼容范围

1. 打开 Windows 程序，自动识别可用局域网 IPv4，并搜索 LanCast 与 DLNA 电视。
2. 选择 LanCast 接收端后自动填入地址与公开指纹；输入电视上的 8 位配对码，核对完整指纹，再在电视上允许连接。
3. 选择屏幕或窗口，点击“开始投屏”，或选择 MP4 视频文件。系统声音可能包含其他应用的播放内容。
4. DLNA 电视选中后无需配对码，可播放 MP4；屏幕直播仍须先通过“测试电视兼容性”。拉流成功不等于用户已经看见画面或听见声音。
5. 最小化或“收到托盘”只隐藏窗口，不停止控制轮询或媒体。单击托盘恢复，右键提供打开、停止和退出。关闭窗口退出；存在分享或配对时先提示。托盘注册失败时保留可访问窗口，Explorer 重启后尝试重新注册。

多网卡/VPN 或设备无法发现时，展开“高级设置”，选择网络或手动填写电视地址及完整指纹。主机网卡不再需要手写 IP。自动发现指纹需电视端使用本轮共享核心；旧版电视仍支持原有邀请字符串和手工指纹。Android/Apple 的对应自动填写体验由后续 [D14](17-Android与Apple连接体验.md)补齐，旧发送端仍可手动输入新接收端的 8 位邀请。

## 安全边界

- mDNS 仅增加可选的公开 `fingerprint` TXT 属性，不广播配对码、私钥或授权信息。扫描只接受恰好 64 个十六进制字符，缺失/错误时视为旧版，不自动建立信任。
- Windows 每次连接前显示完整指纹供电视侧核对，默认取消；实际 WSS 继续绑定完整 SPKI SHA-256。没有取消 TLS 校验，也没有将发现结果当成已配对设备。
- 一次性邀请改为安全随机源生成的 8 位十进制码（含前导零）；仍为 120 秒有效、最多五次尝试、一次使用、电视明确确认。其他 nonce、签名及媒体 token 仍使用原有随机长度；没有统一缩短秘密。
- 信任仍只在当前进程/会话有效，不落盘记住电视，不自动恢复已撤销的捕获授权。永久信任、QR 导入与免输入配对仍是后续独立设计事项。
- DLNA 继续使用局域网明文媒体，与自有 WSS/SRTP 的安全状态分开表述。

## 模块与依赖方向

| 模块 | 职责 | 不承担的职责 |
|---|---|---|
| `windows/src/main.cpp` | 程序入口 | 布局、网络、业务状态 |
| `app.cpp` | 每窗口的会话状态、命令/事件编排、输入校验、来源选择与启停 | 绘图、网卡枚举、托盘 API、编码算法 |
| `view.*` | Win32 控件、字体、按钮/列表绘制、DPI、滚动与焦点 | Rust FFI、媒体调用、网络请求 |
| `network.*` | GetAdaptersAddresses 枚举、IPv4 过滤、GetBestRoute2 选本机源地址 | UI、外网探测、控制协议 |
| `device_catalog.*` | 有界发现记录归一、按协议和设备 ID 去重、合并列表 | 配对授权、TLS、自动信任 |
| `tray.*` | 通知区图标、菜单、隐藏/恢复、Explorer 重启 | 停止媒体实现；只向窗口发送操作 ID |
| `media.*` / `windows/media` | C ABI 适配 / 独立采集编码传输 | 桌面 UI 布局与发现 |
| Rust `discovery` / `auth` / `control` | 公开发现提示、短期邀请限制、已绑定 TLS 的配对与会话 | Windows 窗口或采集对象 |

编排层持有实例状态，消除旧入口文件的可变全局会话字段。网络地址保存在编排状态，不用隐藏输入控件充当存储。架构检查禁止视图、托盘、网卡和发现列表反向调用 FFI/媒体，并禁止编排层直接调用这些平台实现 API。

后续新增皮肤只改 view，增加网卡策略只改 network，增加新的发现类型需新增目录映射及契约测试。当前 app 仍显式分派两条媒体路线；尚未抽象成通用插件注册或跨平台统一 UI，避免把目录拆分描述成业务编排已完全通用化。

## 生命周期与异步结果

扫描两种协议时合并结果，不再用后返回的列表覆盖先返回的列表。`scanGeneration` 为本地可选命令字段，结果原样返回；旧宿主可忽略它，Windows 忽略超时或旧扫描的结果。记录按协议加设备 ID 区分，选择保留同一键，切换设备清空旧指纹和配对码。

配对/投屏/文件准备期间锁定设备、网络和来源，避免异步任务拿到变更后的目标。实时投屏禁用文件暂停/跳转；停止使媒体代次失效，等核心 `stopped` 后才允许下一轮分享。取消正在等待的配对通过 shutdown 打断旧核心；普通停止不抢先销毁核心。退出最多等待三秒停止，随后关闭句柄和窗口；断网或电视异常时不承诺远端一定收到停止通知。

## 体积与清理

保留 Win32，新增调用均来自 Windows 系统库，不引入浏览器、Qt、.NET、字体包或图像运行时。ICO 复用 Android 既有 LanCast 标识，包含 16–256 像素尺寸；`generate_icon.py` 只在开发时使用 Pillow，构建与运行读取已提交 ICO。图标写入 EXE 资源，窗口、任务栏和托盘共用。

移除旧 main 内嵌表单、两组独立扫描按钮、“使用设备”中间步骤和空的媒体 `pump()` 接口。新增测试程序不进入用户安装目录；产品包仍是一个 EXE、三个 DLL、许可与说明材料。本次新增功能会增加少量代码/资源，不能将源码整理等同于压缩包缩小。具体清理字节数与产物结果见 08 的本轮记录。

## 验证与剩余验收

可复现命令：

```text
python scripts/check-architecture.py
python -m unittest discover -s scripts/tests
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --all-features --locked
ctest --test-dir windows/build -C Release --output-on-failure
python scripts/verify-windows.py
```

`desktop_contract` 覆盖局域网地址、双协议同 ID、去重、空/IPv6优先地址、旧版缺失指纹、畸形发现记录。`view_contract` 创建真实 Win32 控件，验证资源图标、默认折叠、展开不重叠、小窗口滚动及收起；通知区可用时验证隐藏、继续处理计时器、恢复和删除后重新注册；不可用时明确输出SKIP。可选参数导出测试示例界面供检查。Rust 测试覆盖码格式、次数、过期、单次使用，以及原有配对拒绝/连接关闭与恢复回归。

Windows MSVC 完整产品构建、其他平台共享核心回归及最终结果在 [08](08-实施进度与审阅入口.md)记录。原生测试截图是布局示例，不是连接真实电视的证据。多 DPI/多显示器拖动、Explorer 重启、托盘长时投屏、Wi-Fi/VPN 切换及真实电视音画仍需实机验收；没有可用电视或测试能力时不标记为已完成。

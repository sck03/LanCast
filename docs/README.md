## 固定方向

- Android业务用Kotlin；共享控制与网络用Rust；原生媒体与Windows客户端用C++20；Apple使用Swift与独立Objective-C++音频适配。
- v1.0同时建设：自有接收端WebRTC镜像、受限电视DLNA桌面直播、视频文件直放。
- 自有镜像使用H.264/Opus；DLNA直播使用H.264/AAC-LC/MPEG-TS；文件播放优先保留原始MP4。
- 不引入GStreamer、Electron、Qt、.NET作为必需依赖。D08采用Windows固定源码libdatachannel/Mbed TLS/libopus、Android固定上游libwebrtc AAR及只负责TS的FFmpeg子集；定制Android源构建尚未完成。
- Android一个发送App（API29+），三个接收变体：Standard（API23+）、Legacy（API21/22主要目标）与AirPlay（API23+）。Standard/AirPlay用Media3，Legacy用系统MediaPlayer。默认每个APK含ARM32/ARM64，按产品选择下载；tvOS为专用接收端。
- 模块有明确依赖方向；协议、平台、播放器和存储均通过窄接口接入。未来扩展以增加适配模块为主，不重写业务核心。
- 优先免费、开源库；不采购商用投屏SDK，不以开源库许可证替代分发时的codec/平台条款核查。
- D15新增独立Android Airplay接收变体：修正并固定rairplay/PlayFair，现代与旧配对入口、系统解码播放、后台等待、电视确认和单路租约；默认关闭。18维护合同、19保留调研、20维护实现和GPL组合包边界，08记录构建/测试与待完成真机验收。

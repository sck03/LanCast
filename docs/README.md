# LanCast 全新设计文档

版本：1.0 设计基线 + D09–D15设计扩展，统一配对协议v2；应用默认版本：0.5.1 / 7 开发版（build-config.json）；日期：2026-10-08。D15为按需AirPlay接收设计，尚未实现。

本目录记录目标架构；源码位于仓库的 crates、core、android、windows、media-native、apple。目标合同与已完成情况分别维护，不能把目标表当作当前能力表。

**先阅读 [08 实施进度与审阅入口](08-实施进度与审阅入口.md)。** 已清理过期且含失效原型引用的旧设计文档；需要追溯时查看[清理前的Git历史](https://github.com/sck03/LanCast/tree/512df71/docs/archive)，不将其作为当前设计依据。

## 固定方向

- Android业务用Kotlin；共享控制与网络用Rust；原生媒体与Windows客户端用C++20；Apple使用Swift与独立Objective-C++音频适配。
- v1.0同时建设：自有接收端WebRTC镜像、受限电视DLNA桌面直播、视频文件直放。
- 自有镜像使用H.264/Opus；DLNA直播使用H.264/AAC-LC/MPEG-TS；文件播放优先保留原始MP4。
- 不引入GStreamer、Electron、Qt、.NET作为必需依赖。D08采用Windows固定源码libdatachannel/Mbed TLS/libopus、Android固定上游libwebrtc AAR及只负责TS的FFmpeg子集；定制Android源构建尚未完成。
- Android接收分Standard（API23+）与Legacy（API21/22主要目标）；Standard用Media3，Legacy用系统MediaPlayer，不锁住一套停止升级的旧Media3。发送App为API29+。
- 模块有明确依赖方向；协议、平台、播放器和存储均通过窄接口接入。未来扩展以增加适配模块为主，不重写业务核心。
- 优先免费、开源库；不采购商用投屏SDK，不以开源库许可证替代分发时的codec/平台条款核查。
- D15新增Android电视端按需AirPlay接收：AP2优先、向下兼容AP1/legacy镜像，默认关闭、手动启用、无开机自启动。现代AP2优先验证rairplay，UxPlay保留C/C++镜像/兼容参考，Android对比CastBay与android-airplay-server；19记录调研，生产后端及实现仍待完成。

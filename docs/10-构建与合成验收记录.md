# 10 构建与合成验收记录

日期：2026-10-03。本记录区分可复查的构建证据、自动化验证和本机合成硬编验证；不替代06中的真实发送端—电视验收。

## 可复查入口

- 程序源码提交和最终工作流链接在08的验证记录中维护。
- Actions产物：三个Android调试APK、Windows开发包、Windows合成诊断程序、Android/Windows原生源码与重链接材料、Rust依赖报告。
- Windows包内 binary-dependencies.json 记录四个PE文件的SHA256、大小和导入项；验证不存在未分发的VC/GCC运行时依赖。
- scripts/github-ci.py支持按运行ID查询日志和下载指定产物；下载只写入本任务缓存，并检查解压路径和大小。

## 本机环境与方法

环境为Windows 10 Enterprise LTSC 1809（10.0.17763）、AMD Radeon RX 580 2048SP，驱动31.0.14051.5006。**该系统低于项目WGC发送端的Windows 10 22H2基线，不能据本次合成测试宣称支持1809的窗口/屏幕捕获。** 此次只验证GPU颜色转换、硬件MFT H.264、系统AAC、TS封装及HTTP起播路径。

media_probe的synthetic标志固定启用：它生成GPU彩色画面与PCM音调，不创建WGC窗口/显示器捕获源，不启用WASAPI或麦克风。诊断程序应放到开发包同目录，使它加载同目录的lancast_ts.dll。

在仓库根目录执行，先将诊断exe放入开发包目录：

```powershell
$package = 'C:\LanCast' # 改为开发包实际目录
New-Item -ItemType Directory -Force .cache | Out-Null
& "$package/media_probe.exe" "$package/lancast_rtc.dll" "$PWD/.cache/new-synthetic.ts"
python scripts/validate-hardware-probe.py .cache/new-synthetic.ts --ffmpeg <ffmpeg路径> --report report.json --commit <程序提交>
cargo run --locked -p cast-adapters --example validate_ts -- .cache/new-synthetic.ts .cache/joins
cargo run --locked -p cast-adapters --example validate_live -- .cache/new-synthetic.ts .cache/joins
```

硬件诊断必须使用包含硬件MFT的真实环境；没有硬编的机器应明确失败。验证脚本只依赖Python标准库和FFmpeg，检查H.264/AAC格式、BT.709标记、三时刻RGB内容、440Hz提示音、PTS/DTS及样本SHA256。

所有join输出进一步以原始时间基解码：

```sh
ffmpeg -v error -xerror -i joins/http-0.ts -fps_mode passthrough -enc_time_base:v demux -f null -
```

对可变帧时刻，null输出的推测帧率时间基可能把两个不同时间戳取整到同一个整数；不能据此断言原始TS有重复DTS。验证需保留demux时间基，并直接检查原始包PTS/DTS严格递增。选取TS测试画面时使用输入后的`-ss`进行精确解码，避免未索引TS的快速寻址落到下一关键帧。

## 已检查的场景

| 场景 | 证据 | 限定范围 |
|---|---|---|
| Rust控制/文件/身份/生命周期 | 工作区测试、clippy、角色feature检查 | 自动化，不代表真实网络/电视矩阵 |
| TS中途加入与分片 | 三个加入位置、四种真实PAT/PMT/PES重分片，输出解码 | 项目产生的单节目H.264/AAC流 |
| HTTP/UPnP闭环 | 1.0/1.1、HEAD、Range、Load/Play/Stop、撤销；电视换源后不误Stop | 模拟renderer，不测电视预缓冲 |
| RTC互联 | Windows本机ICE/DTLS/SRTP、H.264/Opus RTP、过期协商拒绝 | 不等于Windows到Android解码 |
| DLL生命周期 | 重复load/create/stop/unload，无销毁后回调 | 合成来源、无真实桌面 |
| GPU/MFT/TS | 本机合成编码及独立解码、颜色/音调/时间戳检查 | 不包含WGC来源和真实WASAPI采集 |
| Android | 三个APK构建、lint、JNI和16KiB/4KiB ABI检查 | 无真机运行记录 |

最终样本记录见[rx580-c214877.json](validation/rx580-c214877.json)。对应程序CI全部通过，最终样本173个视频包、2,388,352字节，原始PTS/DTS严格递增；三色采样为(253,0,0)/(0,255,0)/(0,0,253)，音调主峰440Hz。四个exe/DLL共16,170,818字节，逐一与CI产物哈希比对；此数不包含源码、许可或诊断工具，不是压缩包或运行内存大小。

延迟、可听音画同步、两小时稳定性、真实电视兼容率、WGC与WASAPI来源切换仍须按06验收，不能从短合成样本推断。

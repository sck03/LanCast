# 26 截止与资源退出维护（D22）

日期：2026-10-25；开发版本0.6.7 / 15。实现、运行及源码对应关系集中记录在[08](08-实施进度与审阅入口.md)。本轮延续现有模块边界，不新增应用运行依赖。

## 固定截止与存储

`cast-core/recovery`独占首次20秒与断流15秒的纯时间策略。`report`先检查截止再接受状态，`poll`只交付一次Stop；首次失败不能延长首次连接总预算。适配器继续绑定会话和协商代次，平台媒体不复制重试算法。

`cast-adapters/blocking_io`拥有每核心4个阻塞任务名额、关闭令牌与命令代次。文件打开、资源元数据、设备档案读取、查询和持久化均不在异步命令线程执行同步磁盘调用。取消会阻止尚未开始的任务、迟到结果和旧快照发布；已进入操作系统的磁盘调用不能强制中止，任务返回后自行释放资源。不得为此无限增建线程。

设备档案schema 2使用设备→配置→证据映射，读取schema 1时迁移原有单份证据；保存前淘汰超过30天的记录。最多256个设备、每设备16份配置、序列化文档1MiB，时钟回退的证据仍不能通过验证。原子替换、失败恢复及取消检查由存储模块负责，Runtime只编排用例。

本机信令直接从已验证的JSON Value转换成Message，避免再次生成字符串和重复解析；仍执行总大小、版本、类型、SDP及ICE限制。远端文本继续拒绝重复键。

文件服务保留有界64KiB读取，顺序读取复用当前位置，Range切换或读取取消后必须重新定位。没有引入跨语言共享缓冲或无界缓存。Runtime独立拥有文件、桥和直播HTTP任务，撤销后等待退出；超过回收预算则中止并等待任务，之后才发送stopped。接收控制监听保持原有常驻语义。

## 平台媒体所有权

| 模块 | 本轮职责 | 扩展约束 |
|---|---|---|
| Windows MediaSender | 专用线程串行创建、命令和销毁；32项命令上限；退出后发media.stopped | 窗口线程只提交请求和消费复制事件，不等待驱动或RTC全局清理 |
| Windows DesktopApp | 按媒体代次记录正在退出的实例，控制与媒体两方完成后开放新分享 | 旧完成事件只能清除对应实例；退出等待不能用定时器假装资源已释放 |
| Android RtcPeer | 初始化失败回滚；协商范围内等比、偶数尺寸；清理完成通知 | 原生资源仍由媒体worker持有；停止请求与完成通知分开 |
| Android宿主 | Lease等待RTC清理，发送busy等待RTC/DLNA全部媒体所有者退出，空闲时关闭未使用核心 | 后台分享、连接、扫描和待授权不因界面离开被误停；DLNA音频join超时仍持有退出屏障 |
| Apple RtcSession / SystemAudioDevice | 音视频独立入口预算，录音代次与交付互斥，源PTS映射到48k采样时钟 | 停止后的旧PCM不得进入新录音；丢弃样本的时间间隔不能压缩，实际同步需以RTP与可听测试确认 |

Android Legacy/Standard播放器在局部作用域持有待初始化资源，配置失败立即释放；宿主事件处理异常转换为一次终止事件，不跨越主线程边界。资源回收失败不应让另一项独立回收被跳过。

Apple的`AudioTimeline`只计算源PTS与输出采样位置，不依赖UI或WebRTC。每个录音代次建立新原点，拒绝重复、回退、无效和溢出时间；时间缺口重建转换器以丢弃旧重采样历史。该映射保留间断，不代替真实音画同步测量。

AirPlay控制连接继续最多8路、头16KiB、体1MiB。每个请求含加密片段和消息体有15秒绝对预算，配对前连接有60秒总预算，并保留30秒空闲时限；收到少量字节不能无限续期。完整请求恢复下一次预算，正常长时间镜像不受连接总时长限制。未支持的buffered audio仍明确拒绝，删除未调用的setup实现。

## 构建与清理

Windows构建在明确的staging目录生成包，验证文件白名单、许可证、完整相对路径哈希、PE及普通/延迟DLL导入后替换旧交付目录。系统DLL允许集合由校验模块维护，其他依赖必须进入明确包清单。路径和链接检查在递归处理前执行。

开发构建允许未提交修改，但记录`source_dirty`和源码摘要；对应源码归档要求干净工作树，并与构建前报告一致。不能用打包时重新记录HEAD掩盖二进制来源。CI路径包含共用校验器；main复用JNI执行附加Android Release检查，并保存独立报告。

移除core未使用的tempfile、把仅测试使用的serde_json移至开发依赖，移除AirPlay未使用的rand 0.8及独占传递项。删除无调用的DLNA包装/未读字段和不可达AirPlay setup；`route.plan`仍是公开本机命令，保留其兼容入口。第三方来源、许可证、锁文件和原始媒体样本不作为无效文件清理。

## 回归与性能边界

新增回归覆盖：截止后状态先于tick、取消磁盘工作、档案迁移/多配置/过期淘汰、取消持久化回滚、HTTP停止后端口复用、文件读取取消、Android采集尺寸、Windows慢创建/命令/销毁、Apple录音停止/时间缺口、AirPlay慢速与加密分片请求及打包反例。

本地可执行检查、平台构建、具体源码及限制以08为准。Windows虚拟GPU跳过、Android纯JVM或直接SDK编译、Apple模拟器/合成样本均不能替代真实采集、驱动故障、弱Wi-Fi、CPU/RSS、端到端延迟、可听同步或两小时长稳。JNI长期附着、音频重排和更复杂缓冲池须有性能证据后再评估。

# D48 宿主状态与资源收敛

2026-11-20更新：当前0.8.0的就绪状态、解码重试、采集队列、能力拆分及上游核对以[29](29-会话就绪与能力模块重构.md)为准；下文保留原专题及历史验证语境。

2026-11-20，开发版 0.7.0 / 41。本轮直接更新当前客户端与本机命令合同，不保留旧应用接口、旧路由模型或旧统计兼容入口。系统版本支持、标准 DLNA/AirPlay 互通与许可证边界不因此删除。

## 生命周期修复

- Android 系统文件选择与授权请求由 SenderRuntime 持有，HostCoreLease 将可见性、外部请求和活动媒体分开。文档选择器期间保留持有 DLNA 目录的核心；真正释放核心时同步清空目录与选择，返回前台重新发现，避免使用新核心中的旧设备 ID。
- 本机命令失败的 body 固定携带 code、op、requestId、generation；未提供关联值时为 null。Android profile.check 只完成匹配请求，终止错误仍释放整个会话。Windows 忽略过时代次的错误。
- macOS 刷新来源保留稳定 ID；来源消失清空选择，不自动选中显示器。并发刷新的旧结果不能覆盖新列表。
- iOS App Group 将一次性连接票据与广播状态分开。状态包括 prepared、starting、broadcasting、finished、failed，绑定票据 ID。扩展每 5 秒更新状态和读取停止请求；宿主在前台恢复时及前台等待期间对账。准备超过 120 秒或活动状态超过 15 秒未更新时解除锁定。状态文件不包含系统采集授权；扩展始终拥有采集与媒体，停止请求不代替 ReplayKit 授权。
- Android 与 Apple 接收端订阅网络变化；绑定 IPv4 消失时撤销发现、连接与媒体，清空旧配对码，提示重新启动接收。不会自动将旧授权绑定到新接口。

## 资源与模块边界

| 所有者 | 职责 |
|---|---|
| runtime/live_commands | DLNA档案读写、测试确认和直播准备，不直接持有平台采集器 |
| runtime/command_context | 保存本机命令关联信息，统一构造失败事件 |
| runtime/bridge_resource | 一个活动媒体代理及其取消、替换、任务等待；取消过程中保持任务所有权 |
| Android FileBridge | 把代理请求关联到当前播放器，只调用已有 ControlSession |
| Android HostCoreLease | 纯生命周期保留策略，可独立回归，不依赖 Activity/JNI |
| Apple HostLifecycle | 纯来源选择与广播状态时效契约，不依赖 SwiftUI/ReplayKit |
| Windows capture_pacing | 纯采集节奏策略，不持有设备或 UI |

Apple AVPlayer 与 Android Legacy MediaPlayer 共用接收核心的固定指纹 HTTPS→loopback 代理。bridge.create 必须带 requestId，bridge.ready 回传同一 ID；bridge.close 只关闭匹配资源，旧关闭请求不会关闭新代理，也不会停止 WSS 接收监听。全局 stop/shutdown 仍撤销资源。省去每次文件播放额外的核心线程、两条 Tokio 工作线程和身份生成；标准 Android Media3 继续直接使用固定指纹 HTTPS。

复用当前 DLNA 播放控制器与 HTTP 连接池。删除无消费者的 Android/Apple RTC 每秒统计采集、序列化与传输，移除 statistics、live.stats、route.plan 及独占类型。事件邮箱只保留有界 FIFO、大小限制、关闭唤醒和保留终止错误。cast-domain 保留真实协商使用的 Profile；cast-core 仅保留 RTC 恢复策略。

移除 pair.accepted 中未消费的 deviceToken、receiverPublicKey、receiverDeviceId 和 session.accepted 的 audioPolicy。真实身份验证仍由固定 SPKI、挑战签名、一次性配对码和接收端确认完成。信任仍只作用于当前会话。

## 平台适配与采集节奏

Android 发送端显示 session.state=ready，并和 Windows 一样补齐自有接收端文件音量控制。DLNA 当前仅实现 AVTransport，禁用不支持的音量入口；Apple DLNA 发送仍属于未实现产品范围。

Windows 窗口大小变化时释放借用帧与旧视图，重建 WGC 帧池，保持原捕获项与编码输出尺寸。静态 RTC 画面只在请求关键帧或 1 秒保活时重复编码；DLNA 保持连续视频时钟。循环按下一帧期限等待，有声模式最多 10ms、无声最多 33ms，保留编码器排空、音频与停止检查。原始帧缓存仍有界保留，未将异步编码中的样本当作可复用缓存。

## 验证与后续扩展

回归入口包括 Rust 真实核心的错误关联、代理替换/过期关闭/监听存活，Kotlin HostCoreLease，Swift HostLifecycle，以及 C++ capture_pacing_contract。各平台构建和实际执行结果在 08 与 validation 记录；不沿用旧提交通过结果作为本轮证据。

增加功能须先明确状态所有者、请求完成路径与资源释放边界。不得重新加入仅测试调用的生产入口，也不为缩短大文件引入空转协调层。性能变化以减少的任务、唤醒和重复处理描述，CPU/RSS、GPU、真实端到端延迟与两小时长稳仍需设备测量，不能从代码推算提升百分比。

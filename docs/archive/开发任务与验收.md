# 开发任务与验收

与[研发决策与编译基线](研发决策与编译基线.md)、[实现规格](实现规格.md)、[安装限制](设备接入与安装限制.md)共同指导实现。产品代码尚未创建，`prototype/`是验证与迁移基线。下表按依赖执行，不把调研完成当功能完成。

## 1. 实施任务

| 任务 | 依赖 | 需要编写的内容 | 完成条件 |
|---|---|---|---|
| T01 工程 | 无 | 产品workspace；接收standard/legacy、sender、player-api/两个实现模块；固定工具链 | 两变体依赖图分离且可构建；与prototype互不覆盖 |
| T02 媒体库 | T01 | 固定WebRTC源/DEPS、补丁、GN；Android ARM32/64、Windows x64库 | 可复现构建清单，native加载和16KB布局检查通过 |
| T03 Kotlin接收 | T01/T02 | Java迁移、TV焦点、状态、音频、Surface/关闭、两Media3实现 | 720p/1080p接收、停止/返回/焦点无泄漏，不是仅能安装 |
| T04 Android发送 | T02 | MediaProjection、前台服务、PlaybackCapture、10ms音频、权限撤销 | API29/34+允许来源有音轨，拒绝/静音/撤销正常，无麦克风替代 |
| T05 Windows发送 | T02 | Win32、WGC、D3D11/MF H.264、WASAPI、音频设备切换 | 全屏/窗口/系统声音/停止正常，CPU回读不是默认路径 |
| T06 控制 | T01 | Rust WSS、mDNS、可信配对、v1协议/状态机、撤销、幂等/重连 | 未授权无媒体，15秒恢复预算有效，协议/权限/边界测试通过 |
| T07 设备路由 | T06 | installed/blocked/unknown，自有/DLNA/系统说明入口 | 受限电视不被强制要求装APK，未知能力不显示成功 |
| T08 文件直放 | T03/T06 | SAF/Windows句柄、令牌、HTTP Range、MP4/seek | 200/206/416、断流/撤销、播放/暂停/seek和两播放器通过 |
| T09 DLNA发送 | T07/T08 | SSDP、受限XML、AVTransport、RenderingControl、状态轮询 | 禁止安装App的真实电视可直放视频，不把DLNA当镜像 |
| T10 v1.0发布 | T03–T09 | 设备矩阵、长稳、同步、温度、安装、签名/回退 | 必需项通过或明确从支持名单排除，含受限电视场景 |
| T11 v1.1维护 | T10 | 修复设备兼容、重连和诊断问题 | 不以堆外部协议代替已有质量修复 |
| T12 v1.2 Apple | T10 | iOS/iPadOS16+ Swift与ReplayKit扩展、分发/权限/资源测试 | 真机到自有接收端；Apple TV/AirPlay说明准确 |

T04/T05依赖媒体基础，可在工程完成后分别开发；这只是任务依赖规划，并非已经并行实现。自建库和真实系统音频先完成，不以默认麦克风音轨或仅依赖下载成功冒充完成。

## 2. 自动化验证范围

- Rust：协议版本、身份/令牌、角色、幂等、状态转换、超时、队列/消息边界、关闭后迟到事件。
- 媒体：合成视频/音轨互通、SDP前ICE、停止、重复会话、恢复；真实同步仍需外测。
- Android：录屏拒绝/撤销、前台服务、尺寸变化、离开Activity、播放/镜像互斥、两变体manifest/依赖图。
- HTTP：HEAD/GET、Range首尾/越界/空文件、令牌撤销、路径遍历、只读句柄、IP限制。
- DLNA：缺服务XML、相对URL、DTD/大响应/恶意LOCATION、SOAP fault、查询重试及写超时后查询。
- 构建：版本锁定、ABI、native布局、许可证、签名；禁止一个APK混入两套Media3，禁止关闭TLS验证。

复用原型测试时，针对已改变接口补充验证。产品工程未落地时仅执行 `prototype/README.md` 的命令；本页任务不是已存在的可运行脚本。

## 3. 真机矩阵与指标

| 对象 | 必测内容 | 发布门槛 |
|---|---|---|
| Legacy API21/22 ARM32盒子/投影 | JNI/EGL/H.264/Opus、Media3 1.8.1、720p30、MP4/seek | 2小时无崩溃/持续积压，停止后释放 |
| Standard API23/25/28 | 1080p30、Media3 1.11.1、声音/焦点、网络切换 | 能力不足正确降档，显示原因 |
| 新Android ARM64 | 16KB要求、新权限、1080p60 | 不因minSdk低而跳过新系统检查 |
| 手机API29/34+ | 允许/禁止采集的声音、全屏/单应用、拒绝/撤销 | 音轨与显示一致，无越权/残留采集 |
| Windows10 22H2/11 x64 | 屏幕/窗口、系统音频、设备切换、锁屏/源关闭 | 停止/恢复正确，无后台残留 |
| 禁止第三方App但有DLNA的中国电视 | MP4、暂停/seek/停止、故障/隔离 | v1.0必须有实机，不安装接收APK |
| 系统AirPlay/Miracast或无共同协议 | 路由说明、按钮、失败状态 | 不显示虚构的LanCast连接/统计，明确系统或盒子路径 |
| iPhone/iPad/Apple TV说明 | App Store/管理限制、tvOS、AirPlay/WebRTC区别 | 不暗示Android APK可装Apple TV，或AirPlay可发现自有WebRTC |

目标：健康LAN上Standard1080p30镜像延迟p95≤200ms，Legacy720p30≤350ms；音画偏移绝对值p95≤50ms。以上不是已测结果，用闪光/点击声测试片及外部摄像/采集卡测量，RTT不等于画面延迟。DLNA按设备能力验收，不套用WebRTC交互延迟指标。

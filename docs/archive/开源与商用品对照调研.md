# 开源与商用品对照调研

调研日期：2026-10-03。目的：确定 LanCast 的产品范围、Android 语言、媒体引擎、系统版本及构建方案。最终决策见[研发决策与编译基线](研发决策与编译基线.md)。

本次检查了下列开源项目的关键源码、构建文件或上游文档，以及商用产品的官方页面。不是对全部仓库的逐行审计，也没有运行商用品进行延迟、画质和稳定性横评。商用品的内部协议、实现语言、服务器路径和授权合同未公开的部分均记为未知，不以宣传语推断技术实现。

### 构建来源中的一个实际问题

`webrtc-sdk/webrtc-build` 的 `m150.7871.01` release 存在，但该 tag 根目录的 `webrtc_version.yaml` 仍写着 M92，旧的 settings 还指向可变 `main`。因此不能直接复制上游根目录脚本并宣称已可复现 M150 构建。产品自建库以明确的 WebRTC 源提交、其 DEPS 和项目补丁为准；构建清单记录所有实际解析的依赖 revision，不跟随浮动分支。

依据：[release](https://github.com/webrtc-sdk/webrtc-build/releases/tag/m150.7871.01)、[旧 version 文件](https://github.com/webrtc-sdk/webrtc-build/blob/m150.7871.01/webrtc_version.yaml)、[构建目录说明](https://github.com/webrtc-sdk/webrtc-build/blob/m150.7871.01/build/README.md)。上面的源码基线与 Maven AAR 的精确一一对应关系尚未证实，不把两者混用为同一 ABI 产物。

## 3. 三条路线的取舍

| 路线 | 优点 | 主要成本 | LanCast 决定 |
|---|---|---|---|
| 通用协议接收器 | 对支持相应协议的手机可免装发送 App | AirPlay/Cast/Miracast 各自认证、系统集成、设备回归；一些能力需硬件/OEM合作 | 不作为 1.x 产品方向 |
| 自有 App + 自写媒体传输栈 | 可控制全部协议细节 | 还需自行解决同步、拥塞、丢包恢复、codec 与跨平台生命周期，研发成本最高 | 不采用 |
| 自有 App + WebRTC 实时媒体 + HTTP 媒体直放 | 可统一采集、协商、缓存、控制与诊断，又复用成熟媒体栈 | 用户需安装自有接收 App；手机需发送 App；仍要做硬件适配 | 采用，构成 v1.0 |

多协议增加的主要问题是测试组合、依赖冲突、常驻资源及维护成本，并非协议数量本身会必然降低每次投屏的帧率。自有端让优化与问题定位更可控，但没有“必定比 AirPlay/Miracast 更快”的实测结论。

## 4. 调研落实为哪些明确决策

1. Android 自编业务代码使用 **Kotlin**；UI 先用 Views/XML。Kotlin 能直接调用 WebRTC Java API，不需要为了接库而选 Java。
2. 实时镜像统一用 WebRTC，首版视频 H.264、音频 Opus；文件直放 MP4/H.264/AAC。首版不做第二种实时传输栈。
3. **两个接收构建变体**：Standard Android6/API23+ 配 Media3 1.11.1；Legacy Android5/API21–22 主要使用，配 Media3 1.8.1。共享 Kotlin/Rust/媒体接口及实时引擎，播放器依赖分别解析。
4. 因中国电视可能禁止安装第三方App，**v1.0即实现DLNA发送控制器**，覆盖已有MediaRenderer的电视视频直放；桌面镜像不能用DLNA替代。1.x不自建AirPlay/Miracast/Google Cast接收栈，系统已有功能仅提供准确的操作指引。
5. 不购买商用投屏 SDK作为 1.x 的基础，不引入云端中转、账户或公网 STUN；局域网核心功能可离线运行。
6. Windows 做原生发送客户端；Android 手机发送端最低 Android10/API29，保证具备使用官方内部声音采集 API 的条件，仍尊重内容方禁止采集的策略。

这组结论并未把一个 APK 当作用户硬性要求。分包原因是维护中的播放器依赖与老系统覆盖存在真实分界，而不是 Kotlin 在新旧系统上需要不同语言，也不是人为划分高低性能版本。

语言依据：[Android Kotlin-first](https://developer.android.com/kotlin/first)、[Kotlin 调用 Java](https://kotlinlang.org/docs/java-interop.html)。工具链依据：[AGP8.13兼容表](https://developer.android.com/build/releases/past-releases/agp-8-13-0-release-notes)、[Kotlin Gradle兼容表](https://kotlinlang.org/docs/gradle-configure-project.html)。

## 5. 安装限制补充

不能将“Android最低支持到5.0”解释成所有Android电视都能安装。厂商商店、签名白名单、固件策略与用户管理权限是另一维度；本次不推测中国电视的受限比例。具体分流和Apple设备差异见[设备接入与安装限制](设备接入与安装限制.md)。

Apple官方资料确认iPhone可通过App Store下载应用，Apple TV具备相应商店的型号可管理tvOS应用，AirPlay镜像需要目标设备确有兼容能力。没有据此推导iPhone App可直接装tvOS，或LanCast的WebRTC接收端自动成为AirPlay接收端。依据：[iPhone App Store](https://support.apple.com/guide/iphone/get-apps-iphc90580097/ios)、[Apple TV用户指南](https://support.apple.com/guide/tv/find-apps-atvb8ee43a39/tvos)、[AirPlay镜像](https://support.apple.com/en-us/102661)。

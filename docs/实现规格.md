# 实现规格：模块接口、会话、媒体与DLNA

版本：LanCast v1.0设计，2026-10-03。本文用于直接拆分开发任务；这些生产接口尚未实现。当前可运行的HTTP原型在 `prototype/`，其协议另见[原型信令v0.1](../prototype/信令接口-v0.1.md)，两者不能混用。

## 1. 模块与依赖方向

| 目标目录/模块 | 责任 | 允许依赖 | 禁止承担 |
|---|---|---|---|
| `core/session` | 身份、会话、状态机、重连、命令幂等 | protocol、capabilities | codec、像素拷贝、Android UI |
| `core/protocol` | v1消息解析、版本与错误码 | serde等基础库 | 平台录屏和播放器 |
| `core/discovery` | 自有mDNS、DLNA SSDP、设备合并 | 受限网络客户端 | 凭设备名猜测安装权限 |
| `core/dlna-sender` | UPnP设备描述、AVTransport、RenderingControl | discovery、media-http | 桌面编码、模拟接收器 |
| `core/media-http` | 单会话本地文件、HTTP Range、令牌与资源寿命 | 只读文件句柄 | 任意URL代理、任意路径读取 |
| `core/ffi` | C ABI、回调、句柄与错误映射 | 以上核心 | 跨语言STL/异常传递 |
| `android/app-receiver` | Kotlin TV UI、授权确认、前台接收、播放器绑定 | control-bridge、player-api、webrtc桥 | 同APK混入两个Media3版本 |
| `android/app-sender` | Kotlin录屏授权、前台服务、文件选择、设备列表 | control-bridge、webrtc桥 | REMOTE_SUBMIX、ADB/shell权限 |
| `android/player-*` | Media3实现、输出时钟、Surface、文件播放状态 | player-api，各自版本的Media3 | 独立重写实时音画同步 |
| `media/webrtc` | 固定源版本与补丁、音视频传输/同步 | native平台API | UI、厂商协议聚合 |
| `windows` | Win32界面、WGC、WASAPI、MF硬编 | Rust C ABI、媒体接口 | 对受保护窗口绕过采集限制 |

Rust控制层只传JSON/小型结构和统计，原始音视频在平台/native层传递。Android `SurfaceViewRenderer` 和Media3播放器互斥占用接收显示区。实时镜像交给WebRTC，文件播放交给Media3，禁止将同一会话的音频和视频分交两个无共同时间基准的播放器。

## 2. 平台媒体与播放器接口

Android用Kotlin定义这些平台内部接口，不作为线协议：

```kotlin
interface MirrorReceiver {
    suspend fun acceptOffer(sdp: String): String // 成功返回answer
    suspend fun addRemoteIce(candidate: IceCandidateData)
    suspend fun stop(reason: StopReason)
}
interface MirrorSender {
    suspend fun start(grant: CaptureGrant, profile: VideoProfile): String // offer
    suspend fun acceptAnswer(sdp: String)
    suspend fun addRemoteIce(candidate: IceCandidateData)
    suspend fun stop(reason: StopReason)
}
interface FilePlayer {
    suspend fun load(media: PlayableMedia)
    suspend fun play()
    suspend fun pause()
    suspend fun seekTo(positionMs: Long)
    suspend fun setVolume(value: Float) // 0..1，不当成设备绝对音量
    suspend fun stop()
}
```

共同事件：`LocalIce`、`ConnectionChanged`、`FirstFrame`、`AudioTrackChanged`、`PlayerState`、`Statistics`、`FatalError`。事件由控制层串行消费，UI只订阅状态。每个实例绑定唯一sessionId，关闭后丢弃迟到回调。重复stop必须安全；不得在WebRTC回调线程同步dispose自身对象。

`CaptureGrant`封装当次MediaProjection授权，不能持久化或跨会话重用。`PlayableMedia`含资源URL、mime、长度、时长及会话级认证信息，不允许传任意本地文件路径给远端。`VideoProfile`明确codec、profile/level、尺寸、fps和码率上限，不只传“高清/流畅”字符串。

### C ABI约定

Rust暴露 `lancast_create(config_json, callback, user_data)`、`lancast_command(handle, request_json)`、`lancast_destroy(handle)`、`lancast_free_buffer(ptr,len)`。create返回非零opaque handle；command返回已接受/参数错误，最终结果通过含requestId的事件返回。所有字符串UTF-8，长度显式传入；Rust分配的返回缓冲只由lancast_free_buffer释放。回调参数只在回调期间有效，需要保留必须复制。

destroy禁止从本实例的事件回调中同步调用，先投递到所属控制线程；destroy返回后不再产生回调。Rust panic必须在FFI边界捕获并转换为错误，C++异常不得越过C ABI。JNI保存引用时明确global/local生命周期，切换到主线程更新View。

## 3. 自有控制协议v1

接收端默认监听TCP8787，路径 `/v1/ws`，只接受WSS。mDNS发布 `_lancast._tcp`，TXT含 `version=1`、随机持久化deviceId、接收变体；不广播令牌或文件地址。端口被占用时报 `PORT_IN_USE`，不能静默同时启动两个接收服务。

新设备先验证电视二维码或手动核对的TLS公钥指纹，再进行配对。二维码包含版本、内网地址、SPKI SHA256指纹、随机128bit以上一次性邀请，邀请120秒过期、使用后撤销。手动模式输入完整指纹或通过已信任设备转交；不能以“忽略证书错误”代替验证。邀请尝试最多5次，超限撤销并在电视重新生成。

电视确认新设备后发放256bit随机设备令牌，与设备公钥绑定，可撤销，Android/Windows使用平台安全存储。设备密钥采用ECDSA P-256；每次配对/恢复由接收方先发送32字节随机挑战（30秒有效、一次性），请求携带对UTF-8域分隔串 `LanCast-auth-v1`、挑战及固定16字节device UUID拼接值的SHA256/ECDSA签名（DER后Base64）。验证签名证明私钥持有，不能只接受请求中自报的公钥。使用平台/成熟密码库实现，不自行实现ECDSA。

API21无法使用新Keystore API时使用兼容实现；安全存储初始化失败则仅本次会话信任，不静默明文落盘。恢复仍需TLS pin、令牌与挑战签名校验，挑战与当前WSS连接绑定。发送端本地HTTPS文件证书的SPKI必须与已配对设备身份一致。

每条消息一个JSON文本帧，最大128KiB；SDP最多96KiB，ICE candidate最多4096字节；同一连接最多32个待响应请求。信令队列使用与原型同等或更严格的字节上限。解析拒绝重复键、非预期类型、过深嵌套及超限整数。

```json
{
  "version": 1,
  "id": "7f9c932b-7a25-4f2c-b57a-1f0342711547",
  "type": "session.start",
  "sessionId": null,
  "body": {"mode": "mirror", "audioRequested": true}
}
```

`id`为UUID，请求内必有；响应含 `replyTo` 指向请求id，事件使用独立id。`sessionId`在创建成功后由接收端生成。所有时间间隔/媒体位置为非负整数毫秒；音视频底层时间戳由媒体引擎处理，不直接比较音频/视频RTP数值。未知major version返回 `VERSION_UNSUPPORTED` 后关闭；未知type返回错误，不默默执行。

| type | 发送方向 | body必需字段/行为 |
|---|---|---|
| `auth.challenge` | 接收端→发送端 | nonce、expiresInMs=30000；每条连接新建、成功/失败后撤销 |
| `pair.request` | 发送端→接收端 | invite、senderDeviceId、senderName、senderPublicKey、signature；已核对TLS身份且对挑战签名 |
| `pair.accepted` | 接收端→发送端 | receiverDeviceId、deviceToken、receiverPublicKey；必须已经电视确认 |
| `auth.request` | 发送端→接收端 | deviceToken、senderDeviceId、signature；已有设备恢复，对当前连接新挑战签名 |
| `auth.accepted` | 接收端→发送端 | receiverDeviceId；之后才允许session/SDP/文件命令 |
| `device.capabilities` | 双向 | role、buildVariant、mirrorCodecs、maxVideoProfile、audio、directPlayMimeTypes；能力声明不能代替后续硬件初始化 |
| `session.start` | 发送端→接收端 | mode=mirror/file、audioRequested；忙时返回BUSY，不自动踢掉旧会话 |
| `session.accepted` | 接收端→发送端 | sessionId、selectedProfile、audioPolicy；明确接收方许可 |
| `rtc.offer` / `rtc.answer` | 发送端/接收端 | sdp、negotiationId；每次协商使用新negotiationId |
| `rtc.ice` | 双向 | candidate、sdpMid、sdpMLineIndex、negotiationId；remoteDescription前暂存 |
| `file.load` | 发送端→接收端 | mediaId、url、mime、length、durationMs（可未知）；仅接受当前可信发送端的受限资源 |
| `playback.command` | 发送端→接收端 | action=play/pause/seek/volume；seek含positionMs、volume含0..1数值 |
| `session.resume` | 发送端→接收端 | sessionId、lastEventId；认证后才可恢复，窗口15秒 |
| `session.stop` | 双向 | reason；幂等关闭，立即释放采集/音频资源 |
| `ack` / `error` | 响应 | replyTo、code、message、retryable；业务错误不包含令牌/文件私有路径 |
| `session.state` / `statistics` | 事件 | state或统计值；统计每秒最多1次，标明未测量值 |
| `ping` / `pong` | 双向 | nonce；5秒心跳，15秒无响应进入断连处理 |

请求id在会话内保留最近256条或60秒的处理结果。重复幂等请求返回原响应，不重复load/seek或新建会话；重复的非幂等协商请求只有匹配negotiationId时可返回原结果。不能把原型“HTTP POST失败就重新配对”的行为直接复制为生产重连策略。

错误码至少固定：`AUTH_REQUIRED`、`PAIR_EXPIRED`、`PAIR_REJECTED`、`BUSY`、`VERSION_UNSUPPORTED`、`CAPABILITY_UNSUPPORTED`、`CAPTURE_DENIED`、`AUDIO_NOT_CAPTURABLE`、`NETWORK_ISOLATED`、`DECODER_FAILED`、`MEDIA_UNSUPPORTED`、`DLNA_UNAVAILABLE`、`SESSION_EXPIRED`、`PORT_IN_USE`。面向用户说明与内部日志分别生成，不能用所有失败统一显示“网络错误”。

## 4. 状态机与资源释放

| 当前状态 | 事件 | 下个状态及动作 |
|---|---|---|
| Idle | 连接未信任设备 | Pairing；验证身份、邀请及电视确认 |
| Pairing | 同意且认证成功 | IdleAuthenticated；拒绝/超时回Idle |
| IdleAuthenticated | session.start且空闲 | Negotiating或Loading；保留会话、初始化资源 |
| Negotiating/Loading | 首帧/播放就绪 | Streaming/Playing；开始统计 |
| Streaming/Playing | 控制/媒体断连 | Reconnecting；暂停新控制，限时保留会话 |
| Reconnecting | 认证恢复且资源可用 | 新negotiationId协商，或查询播放器位置后恢复 |
| Reconnecting | 15秒预算耗尽 | Stopped；停止采集、音频、解码、文件授权 |
| 任意活动状态 | 用户停止、授权撤销、致命错误 | Stopped；必须立即清理，不自动重获录屏授权 |

恢复最多3次，退避1/2/4秒；单次操作也必须服从15秒总预算。权限撤销与停止优先于所有挂起回调。接收端离开接收页面或用户停止服务就终止会话；v1.0不承诺在电视后台长期收屏。前台活动期间保持屏幕亮，释放时清除标志。

## 5. Android采集、解码与播放器

手机最低API29。流程：选择设备并配对 → 用户点击分享 → MediaProjection系统授权 → 启动符合当前targetSdk要求的mediaProjection前台服务 → 创建VirtualDisplay/Surface与音频采集 → WebRTC发送。每次需要新会话时使用合法的新授权；API34+正确处理单应用共享、授权token限制和屏幕尺寸变化。必须实现MediaProjection.Callback.onStop。

内部音频使用AudioPlaybackCaptureConfiguration，只采允许的MEDIA/GAME/UNKNOWN等有效usage，RECORD_AUDIO为运行时授权；不采通话，不申请系统REMOTE_SUBMIX权限。受策略限制时提示“此来源无法分享内部声音”，用户可明确选择静音继续或取消，不切换麦克风。系统撤销录屏时音视频一起停止。

自建WebRTC新增显式PlaybackCapture模式，替换AudioRecord创建来源，保留采集时间与10ms分帧。JNI/库内音频线程使用可复用缓冲，48kHz PCM按库接口接入；静音、重采样和时钟漂移在媒体层处理。拒绝使用“先启动麦克风，再在buffer callback覆盖数据”作为正式方案。

接收端先查询H.264 profile/level、硬解、输出尺寸/帧率，实际初始化成功后才报告就绪。Standard默认1080p30/约6Mbps，Legacy720p30/约3Mbps；硬件不满足降档。帧率持续低于目标90%或解码积压超过设定预算5秒降档；稳定30秒且带宽持续有50%余量才升档。新profile需媒体引擎支持重配置/重新协商，不在应用层直接改字段假定生效。

系统音频播放使用媒体音量路径与音频焦点；来电/其他App争用时按系统事件暂停或降低音量，恢复需要状态一致。电视遥控器能选设备、确认/拒绝、播放暂停、返回和停止。不能依赖触摸屏。

## 6. Windows发送与文件服务

Windows10 22H2/11 x64，WGC按屏幕或窗口捕获，D3D11纹理交给硬件H.264编码器。Media Foundation硬件MFT提供WebRTC VideoEncoder接口；避免CPU截图/JPEG序列。编码器低延迟设置以实际支持为准，不支持的设置不能导致无限重试。软件回退限制为低档并显示状态。

WASAPI loopback采系统播放音频，监听默认输出设备切换并重建音频采集。v1.0“窗口画面”与“系统声音”分别标注，不承诺只录该窗口进程声音；进程级loopback不在首版承诺。浏览器发送只保留为验证原型，不是最终Windows产品UI。

文件选择只打开用户明确选择的只读资源句柄（Android SAF URI、Windows文件选择器）。文件服务提供HEAD/GET、Content-Length、Content-Type、Accept-Ranges，单段Range返回206与Content-Range；越界返回416，包含 `bytes */总长度`；无Range返回200；多段Range首版忽略并返回完整200。不要按URL路径任意打开本机文件。

文件URL包含至少128bit随机、短期、单会话资源令牌，结束即撤销。自有接收端使用HTTPS和既有信任绑定；DLNA兼容路径允许LAN HTTP，页面明确该文件传输未加密。HTTP仅绑定选定LAN网卡，限制目标渲染器IP并阻止重定向到外网。不要把本机所有文件开放成目录列表。

## 7. DLNA发送控制器：首版实现细则

发现：在选定LAN接口向239.255.255.250:1900发送M-SEARCH，ST=`urn:schemas-upnp-org:device:MediaRenderer:1`、MX=2；首次扫描窗口4秒，最多两次请求；按UDN去重，尊重CACHE-CONTROL max-age。Wi-Fi切换清空旧接口结果，用户可重新扫描。不把同一名字的两个IP合并成一台设备。

只读取响应者给出的受限LOCATION：必须是同LAN且与该响应者关联的HTTP(S)地址；限制响应512KiB、XML深度32、禁止DOCTYPE/外部实体、禁止跳转公网/回环/其他设备。解析URLBase及相对controlURL时仍执行相同边界检查，不盲信设备描述URL。

| 步骤 | UPnP动作/行为 | 失败处理 |
|---|---|---|
| 设备确认 | MediaRenderer + AVTransport服务存在；RenderingControl为可选 | 无AVTransport不显示“可播放” |
| 格式提示 | ConnectionManager.GetProtocolInfo（有该服务时） | 缺少时标记未知，以实际播放结果为准 |
| 资源装载 | AVTransport.SetAVTransportURI，InstanceID=0，当前资源URL与DIDL-Lite元数据 | SOAP fault转换明确错误，不盲目重复Play |
| 播放 | AVTransport.Play，Speed=1 | 无首帧观测能力时不伪造首帧时间；查询TransportInfo |
| 暂停/停止 | Pause / Stop | 按设备支持显示控制按钮 |
| 跳转 | Seek，Unit=REL_TIME，Target=HH:MM:SS | 不支持时禁用seek并提示 |
| 音量 | RenderingControl.SetVolume，Channel=Master | 先读取允许范围并映射0..1；无服务隐藏音量 |
| 状态 | 每2秒GetTransportInfo/GetPositionInfo | 3次连续失败结束控制状态并撤销资源授权 |

SOAPAction按设备声明的serviceType构造；HTTP超时5秒；仅查询类请求可自动重试一次。设备可能已执行的写操作超时，先查询状态，不直接重发。DIDL-Lite对XML字符正确转义；protocolInfo使用真实mime/已确认profile，不冒填高阶DLNA profile。

首版只保证可访问本地MP4/H.264/AAC的测试矩阵。电视不支持该文件时提示不兼容，不启动未实现的转码器。DLNA设备没有我们的认证、重连、端到端同步控制和停止确认语义；它独立实现 `FilePlaybackController`，不能伪造WSS `session.accepted` 或WebRTC统计。

## 8. 受限电视与Apple入口

实现[设备接入与安装限制](设备接入与安装限制.md)的数据模型。设备列表只给DLNA设备开放视频播放，不能因“同一局域网可见”开放桌面镜像。系统Miracast/AirPlay指南页不会创建LanCast媒体会话；电视既不能装App又无共同协议时，给出外接接收盒子路径。

iOS/iPadOS16+发送在v1.2：Swift宿主App与ReplayKit Broadcast Upload Extension，通过App Group共享必要的配对配置，扩展独立管理采集/网络与停止；音视频缓冲避免多次拷贝，不写原始录屏到共享目录。宿主退出、扩展资源限制、方向切换及声音策略单独验收。1.x不写tvOS接收App；Apple TV原生AirPlay不等于自有WebRTC兼容。

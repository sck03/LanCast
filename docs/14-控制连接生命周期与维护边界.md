# 14 控制连接生命周期与维护边界（D11）

更新：2026-11-09；D11合同延续至D38（0.6.23 / 31），处理共享控制层的消息预算、停止、配对取消、截止与协作调度、即时发送和维护边界。沿用 Tokio、rustls、tokio-tungstenite，无新增运行依赖。当前仅使用配对协议v2和C ABI 2；具体程序提交和验证证据集中于[08](08-实施进度与审阅入口.md)。

## 模块与依赖

| 模块 | 持有资源与职责 | 扩展约束 |
|---|---|---|
| runtime | 本机命令队列、平台组合、文件/DLNA入口 | 只使用 Client/Server 接口，不读写 WSS 会话表 |
| control/client | 发送连接、信令队列、取消令牌、工作任务 | 使用共享 RTC 恢复协调器，不直接控制采集器 |
| control/server | 监听及连接任务集、连接表、待确认配对、当前会话、授权和消息方向 | 最多8条握手/连接，会话表私有，不依赖 Runtime、DLNA 或文件服务 |
| control/heartbeat | 两端共享的15秒接收截止、到期检查与合法接收续期 | 使用Tokio单调时钟，不持有socket、任务、队列或媒体资源 |
| control/wire | WSS读取缓冲、帧限制、协作预算、JSON消息收发、写超时 | 消费帧前让出耗尽预算的任务；文本与库内Pong刷新均限时5秒 |
| protocol | 单次JSON解码、递归重复键检查、消息结构、规范化预算及有界序列化 | 不拥有网络任务，不依赖平台或Runtime |
| events | 共享宿主事件出口、借用消息直接序列化、按类型合并统计 | 不反向依赖控制或媒体适配器 |
| session / rtc_recovery | 会话所有权、协商代次、恢复动作 | 网络取消不改变录屏授权策略 |
| Android / Apple 界面 | 展示和关闭对应配对确认 | 按 connectionId 匹配，旧确认不得覆盖新请求 |

Runtime仍是本机用例的组合入口；文件、DLNA、设备档案各自维护专用模块。D21删除未被生产流程调用的通用Coordinator及旧WSS续接预算，实际会话所有权继续位于control/server，纯RTC恢复位于cast-core/recovery。宿主事件与资源维护见[25](25-宿主事件与媒体生命周期维护.md)。

D36移除发送连接的250毫秒固定轮询：纯恢复策略提供下一截止，连接适配复用一个计时器，按恢复/接收心跳较早截止唤醒。健康媒体连接不设置恢复计时；本机发送不延长15秒接收心跳。协商重放过滤和确定性回归见[12](12-RTC恢复与协商契约.md#d36-协商重放与按截止调度)。

## D38 WebSocket协作调度与即时发送

旧`receive`只在底层I/O等待时让出任务。WebSocket读取缓冲已经包含大量Pong等控制帧时，循环可以在一次poll内持续消费它们，外层的取消、截止计时和其他信令不能在其间获得轮询。真实WebSocket与16KiB内存双工回归预先装入1024个Pong及一条应用消息，原实现一次接收直接处理到应用消息，未能让出任务；修复后此回归通过。

共享`control/wire`现在在每次读取帧之前调用Tokio协作预算；预算耗尽时才让出，不新增固定轮询、计时器或线程。让出点位于消费下一帧之前，避免`select!`取消接收时丢失已取出的应用消息。该规则同时服务发送、接收和配对等待，不改变15秒应用心跳规则，也不把WebSocket Ping/Pong当作应用心跳续期。

Ping回复直接限时刷新tungstenite已排队的Pong，删除手动构造替换Pong及单独的`send_frame`包装。文本发送与Pong刷新共享5秒写入上限；新增回归覆盖125字节Ping、写入中断后继续接收、Pong载荷与数量、后续应用消息保真，以及无读者时5秒超时。这些是新增保护用例，不表示旧实现都存在重复Pong故障。

Client连接选项及Server接受的TCP socket均开启`TCP_NODELAY`，避免小型配对/协商/ICE控制消息被Nagle算法额外等待；仍由TLS/WSS负责封装、缓冲和错误处理。配置失败沿握手失败路径释放连接。没有新增运行依赖、线程或旧应用兼容分支；吞吐、CPU/RSS及端到端延迟尚未实机量化，协作预算也不承诺硬实时调度。

## D37 共享心跳截止与接收端调度

旧接收端仅在5秒interval到期时检查最后接收时间。消息若在轮询间隙到达，15秒超时会被向后取整到下一次心跳；同时就绪的迟到消息还可能先续期。interval默认补偿错过的tick，任务恢复后可能连续发送多个ping。

0.6.22将两端的接收截止收敛到`control/heartbeat`：仅在截止前收到合法应用消息时续期，本机发送及WebSocket控制帧不能续期，到达截止的消息不能复活连接。接收端复用一个Sleep，等待下次ping和接收截止中的较早时刻；每轮处理与接收消息时也检查到期。ping从本次发送完成后5秒重新计时，不补发积压心跳；首次配对成功仍立即发送ping。收发选择保留公平调度，持续接收不能饿死本机信令。

超时走既有退出路径，先停止当前会话、交付一次`session.closed`，再释放连接名额。停止取消仍能中断整段网络操作。单次阻塞写入继续使用独立的5秒上限，因此这里的15秒是接收有效性截止，不承诺阻塞写入期间也能在同一时刻完成退出；下一轮必须清理，迟到消息始终无效。

回归使用真实WebSocket帧与内存双工传输：偏离轮询网格123毫秒后的最后消息，15秒到期释放会话和连接；暂停12秒后仅发送一次ping；合法远端消息续期但本机ping/pong不续期；截止边界拒绝续期。前两项在统一异步时钟、仍使用旧interval调度的代码上失败，修复后通过。原发送端恢复与心跳测试继续覆盖共享模块。没有新增运行依赖、线程或旧版本回退；删除两端重复的超时常量、接收时间计算和接收端interval，未将调度改进作为CPU/RSS实测。

## 停止的顺序保证

发送端执行本机 stop 时：

1. 命令代次递增，队列中的旧命令失效。
2. Client 的取消令牌中断整个连接循环，包括正在等待的 socket 写入。
3. 等待旧任务退出；该连接的最后一个 disconnected 事件先进入事件队列。
4. Runtime 完成资源清理后发出 stopped。此后旧 Client 不再产生事件。

因此收到 stopped 后可以重新配对，不会有旧连接的迟到回调结束新媒体会话。意外断开后再次显式 connect 会回收已关闭 Client；仍须新邀请和电视确认，不自动重用录屏授权。

D33修复重连回收被外层stop/shutdown取消时的任务所有权缺口：`Client::close`借用并保留工作句柄，等待成功后才清空；Runtime也在关闭完成后才移除Client。取消一次关闭等待不会分离旧任务，随后的停止继续等待同一任务退出。关闭可重复调用；销毁Client仍只请求取消，完成屏障由显式关闭提供。

接收端先清除旧会话，再释放同一设备的连接名额；新连接不能插入到旧会话清理的间隙。连接名额在 pair.accepted 前保留，防止同一设备获得两个成功确认。

接收端信令队列已满或关闭时，停止仍清除本地会话，并取消不能投递信令的连接。取消令牌也包住接收端正在进行的网络写入。

0.6.10补齐发送端同一规则：32项信令队列满或关闭时，`Client::send`先取消工作任务再返回错误。丢失offer、ICE或stop后不能继续维持表面正常的连接；工作任务仍交付最终disconnected事件，平台按既有流程释放媒体资源。原实现仅报错而保留连接，新增回归已复现。

接收监听现在用`JoinSet`同时拥有最多8条握手/已配对连接，优先回收已完成任务再接收新连接，替代独立信号量和脱离所有者的spawn。监听出错时中止并等待全部连接；监听被丢弃/中止时，任务集也中止其连接。强制中止是取消请求，不是额外的同步完成屏障；引擎关闭仍由Runtime负责。原实现中止监听后，未发送TLS数据的连接仍占用socket和身份引用，回归已复现。接收端本机stop继续结束会话并拒绝待确认请求，常驻监听语义不变。

## 解析与缓冲预算

本机命令和WSS文本共享单次JSON解析器：构建Value时递归拒绝重复的解码后键名，随后直接转移到类型化消息。删除独立HashSet和第二次文本解析，保留128KiB文本上限、递归深度保护、尾随数据拒绝、数值规则、未知消息字段拒绝及96KiB SDP/4KiB ICE限制。WSS文本与已有Value的本机信令入口统一检查类型化消息的规范化JSON大小，不额外生成计数用字符串。

两端WSS初始读取缓冲由库默认128KiB改为16KiB，大消息按需增长，最大帧/消息仍为128KiB。96KiB SDP经过1KiB双工传输的回归验证完整交付。每条连接少预留112KiB读取空间；这是缓冲配置变化，不等于实测进程RSS降幅，TLS、消息重组和写缓冲另计。

## D33 控制消息预算与直接交付

旧实现只限制输入原文：恰好128KiB的消息加上宿主事件外壳就会超限；约50KiB的`1e15`数组在JSON规范化后超过160KiB，也能触发`HOST_EVENT_QUEUE_OVERFLOW`并关闭整个Engine。两条解析回归先在旧实现失败，修复后增加WebSocket回环确认异常远端消息只结束对应控制连接，不关闭核心。

类型化消息现在最多127KiB（130048字节），为宿主外壳与接收端补入的64字符指纹预留1KiB。计算包含JSON转义、UTF-8、数值展开和默认字段。原始帧仍限128KiB；SDP和ICE内容限制不变。发送侧也在任何socket写入前执行同一预算，不提供旧的大消息透传回退。后续新增接收端补充字段时，必须保持预留预算并扩展边界回归。

`protocol`的有界writer复用到大小计数、WSS编码和宿主事件编码；超过预算立即停止序列化，避免先创建完整超限字符串。`events::message`借用Message直接输出事件，删除控制路径的`Message → Value → 事件Value → String`中间转换；统计合并键改为UUID值类型，不再每条统计分配字符串。接收端信令移入发送队列，移除一次完整消息克隆。事件JSON结构、FIFO、2MiB总预算、256项容量和统计让位于控制事件的规则保持有效。

新增回归覆盖原文上限、数字展开、最大合法消息加指纹后的交付、超限发送不写socket、异常消息的连接隔离、不同会话统计合并，以及被取消的关闭继续等待旧任务。中间对象与复制减少是代码路径变化；未据此宣称CPU、RSS或端到端延迟已经实测改善。

## 配对等待与界面事件

配对仍要求一次邀请、SPKI 身份校验和用户确认。等待确认期间同时读取连接关闭；发送端离开时立即移除待确认项并退出连接，避免每个取消请求继续占用最多60秒的名额。每个接收服务最多8条并发连接。

新增仅在本机发出的事件：

```json
{"type":"pair.closed","body":{"connectionId":"本次确认请求的UUID","reason":"peer_closed"}}
```

| reason | 含义 |
|---|---|
| accepted | 用户已同意，本次确认等待结束；随后仍须连接/会话成功 |
| rejected | 用户拒绝、接收端停止或确认通道关闭 |
| timeout | 60秒内未完成确认 |
| peer_closed | 对端断开，或在获准前发送了不允许的应用消息 |

Android 与 Apple 按 connectionId 关闭对应确认框；另一设备的关闭事件不会取消当前确认。Android 只展示一个待确认框，多余请求明确拒绝。旧按钮回调在确认已关闭后不再发送批准。

pair.closed仅在本机交付。消息信封version=1与配对协议pairingVersion=2分别描述不同层级，不提供旧配对协议回退。接收端 stop 同时拒绝待确认请求；停止接收应用仍通过 shutdown 关闭运行时。

## 自动化与维护

- 真实 WSS 连续取消12次配对，超过8条并发上限，逐次核对 pair.closed 和旧确认失效。
- 同一发送端3次建立会话、停止和重新配对；检查 disconnected 在 stopped 之前。
- 接收端停止拒绝未完成配对；不读取数据的内存 socket 阻塞写入后，close 仍在1秒测试预算内退出。
- 信令队列饱和时，本地停止清理会话并取消连接。
- D25新增监听中止释放握手、发送队列满/关闭取消连接、大SDP分段读取、JSON值保真及嵌套/转义重复键与非法数值回归。
- 保留 TLS 配对、授权等待中的非阻塞停止、RTC 恢复与新旧信令过滤回归。

运行 `cargo test --workspace --all-features --locked`；Linux 另覆盖已转移文件描述符的释放。Windows/Linux 均运行严格 clippy 和接收端/Legacy feature 检查，五个平台分别构建。

`scripts/architecture.py` 集中维护规则，`check-architecture.py` 保持原 CLI 入口。检查顶层及 target 下的普通/构建/测试依赖，解析 package 别名与 workspace 引用；JNI 仅允许出现在 FFI 的 Android 普通依赖中。纯 domain/core 源目录递归检查，WSS 适配不得反向依赖 Runtime 或其他路线实现。检查不用 assert，因此 python -O 不会关闭检查。

`python -m unittest discover -s scripts/tests` 覆盖上述规则和版本参数。源码扫描属于词法检查，不证明所有 Rust/Swift 语义依赖；变更架构时须同步修改规则、测试和本文。运行与提交证据统一记录在[08](08-实施进度与审阅入口.md)。

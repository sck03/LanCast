# 14 控制连接生命周期与维护边界（D11）

更新：2026-11-07；D11合同延续至D25（0.6.10 / 18），处理共享控制层的停止、配对取消和维护边界。沿用 Tokio、rustls、tokio-tungstenite，无新增运行依赖。当前仅使用配对协议v2和C ABI 2；具体程序提交和验证证据集中于[08](08-实施进度与审阅入口.md)。

## 模块与依赖

| 模块 | 持有资源与职责 | 扩展约束 |
|---|---|---|
| runtime | 本机命令队列、平台组合、文件/DLNA入口 | 只使用 Client/Server 接口，不读写 WSS 会话表 |
| control/client | 发送连接、信令队列、取消令牌、工作任务 | 使用共享 RTC 恢复协调器，不直接控制采集器 |
| control/server | 监听及连接任务集、连接表、待确认配对、当前会话、授权和消息方向 | 最多8条握手/连接，会话表私有，不依赖 Runtime、DLNA 或文件服务 |
| control/wire | WSS读取缓冲、帧限制、JSON消息收发、写超时 | 文本和 Pong 写入均限时5秒 |
| protocol | 单次JSON解码、递归重复键检查、消息结构和字段预算 | 不拥有网络任务，不依赖平台或Runtime |
| events | 共享宿主事件出口 | 不反向依赖控制或媒体适配器 |
| session / rtc_recovery | 会话所有权、协商代次、恢复动作 | 网络取消不改变录屏授权策略 |
| Android / Apple 界面 | 展示和关闭对应配对确认 | 按 connectionId 匹配，旧确认不得覆盖新请求 |

Runtime仍是本机用例的组合入口；文件、DLNA、设备档案各自维护专用模块。D21删除未被生产流程调用的通用Coordinator及旧WSS续接预算，实际会话所有权继续位于control/server，纯RTC恢复位于cast-core/recovery。宿主事件与资源维护见[25](25-宿主事件与媒体生命周期维护.md)。

## 停止的顺序保证

发送端执行本机 stop 时：

1. 命令代次递增，队列中的旧命令失效。
2. Client 的取消令牌中断整个连接循环，包括正在等待的 socket 写入。
3. 等待旧任务退出；该连接的最后一个 disconnected 事件先进入事件队列。
4. Runtime 完成资源清理后发出 stopped。此后旧 Client 不再产生事件。

因此收到 stopped 后可以重新配对，不会有旧连接的迟到回调结束新媒体会话。意外断开后再次显式 connect 会回收已关闭 Client；仍须新邀请和电视确认，不自动重用录屏授权。

接收端先清除旧会话，再释放同一设备的连接名额；新连接不能插入到旧会话清理的间隙。连接名额在 pair.accepted 前保留，防止同一设备获得两个成功确认。

接收端信令队列已满或关闭时，停止仍清除本地会话，并取消不能投递信令的连接。取消令牌也包住接收端正在进行的网络写入。

0.6.10补齐发送端同一规则：32项信令队列满或关闭时，`Client::send`先取消工作任务再返回错误。丢失offer、ICE或stop后不能继续维持表面正常的连接；工作任务仍交付最终disconnected事件，平台按既有流程释放媒体资源。原实现仅报错而保留连接，新增回归已复现。

接收监听现在用`JoinSet`同时拥有最多8条握手/已配对连接，优先回收已完成任务再接收新连接，替代独立信号量和脱离所有者的spawn。监听出错时中止并等待全部连接；监听被丢弃/中止时，任务集也中止其连接。强制中止是取消请求，不是额外的同步完成屏障；引擎关闭仍由Runtime负责。原实现中止监听后，未发送TLS数据的连接仍占用socket和身份引用，回归已复现。接收端本机stop继续结束会话并拒绝待确认请求，常驻监听语义不变。

## 解析与缓冲预算

本机命令和WSS文本共享单次JSON解析器：构建Value时递归拒绝重复的解码后键名，随后直接转移到类型化消息。删除独立HashSet和第二次文本解析，保留128KiB文本上限、递归深度保护、尾随数据拒绝、数值规则、未知消息字段拒绝及96KiB SDP/4KiB ICE限制。已有Value的本机信令入口仍检查序列化大小，不额外生成JSON字符串。

两端WSS初始读取缓冲由库默认128KiB改为16KiB，大消息按需增长，最大帧/消息仍为128KiB。96KiB SDP经过1KiB双工传输的回归验证完整交付。每条连接少预留112KiB读取空间；这是缓冲配置变化，不等于实测进程RSS降幅，TLS、消息重组和写缓冲另计。

## 配对等待与界面事件

配对仍要求一次邀请、SPKI 身份校验和用户确认。等待确认期间同时读取连接关闭；发送端离开时立即移除待确认项并退出连接，避免每个取消请求继续占用最多60秒的名额。每个接收服务最多8条并发连接。

新增仅在本机发出的事件：

```json
{"type":"pair.closed","body":{"connectionId":"本次确认请求的UUID","reason":"peer_closed"}}
```

| reason | 含义 |
|---|---|
| accepted | 用户已同意，本次确认等待结束；随后仍须连接/会话成功 |
| rejected | 用户拒绝、接收端停止或确认通道关闭 |
| timeout | 60秒内未完成确认 |
| peer_closed | 对端断开，或在获准前发送了不允许的应用消息 |

Android 与 Apple 按 connectionId 关闭对应确认框；另一设备的关闭事件不会取消当前确认。Android 只展示一个待确认框，多余请求明确拒绝。旧按钮回调在确认已关闭后不再发送批准。

pair.closed仅在本机交付。消息信封version=1与配对协议pairingVersion=2分别描述不同层级，不提供旧配对协议回退。接收端 stop 同时拒绝待确认请求；停止接收应用仍通过 shutdown 关闭运行时。

## 自动化与维护

- 真实 WSS 连续取消12次配对，超过8条并发上限，逐次核对 pair.closed 和旧确认失效。
- 同一发送端3次建立会话、停止和重新配对；检查 disconnected 在 stopped 之前。
- 接收端停止拒绝未完成配对；不读取数据的内存 socket 阻塞写入后，close 仍在1秒测试预算内退出。
- 信令队列饱和时，本地停止清理会话并取消连接。
- D25新增监听中止释放握手、发送队列满/关闭取消连接、大SDP分段读取、JSON值保真及嵌套/转义重复键与非法数值回归。
- 保留 TLS 配对、授权等待中的非阻塞停止、RTC 恢复与新旧信令过滤回归。

运行 `cargo test --workspace --all-features --locked`；Linux 另覆盖已转移文件描述符的释放。Windows/Linux 均运行严格 clippy 和接收端/Legacy feature 检查，五个平台分别构建。

`scripts/architecture.py` 集中维护规则，`check-architecture.py` 保持原 CLI 入口。检查顶层及 target 下的普通/构建/测试依赖，解析 package 别名与 workspace 引用；JNI 仅允许出现在 FFI 的 Android 普通依赖中。纯 domain/core 源目录递归检查，WSS 适配不得反向依赖 Runtime 或其他路线实现。检查不用 assert，因此 python -O 不会关闭检查。

`python -m unittest discover -s scripts/tests` 覆盖上述规则和版本参数。源码扫描属于词法检查，不证明所有 Rust/Swift 语义依赖；变更架构时须同步修改规则、测试和本文。运行与提交证据统一记录在[08](08-实施进度与审阅入口.md)。
